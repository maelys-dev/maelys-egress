# Releasing maelys-egress

Releases go through the tagged maelys-release socle pinned by the repository.
The workflow `.github/workflows/release.yml` is generated by
`maelys-release adopt`; never edit it by hand and never copy a socle version
number into this guide.

Use a checkout of the tagged socle you intend the product to adopt. Plan first;
only repeat a reviewed command with `--apply`:

```sh
maelys-release check .
maelys-release preflight .
maelys-release cut . X.Y.Z
maelys-release cut . X.Y.Z --apply
```

The applied cut writes the version commit on `release/vX.Y.Z` and opens the
pull request; it never merges its own pull request. Review the diff and wait
for green CI, then merge it. From the same tagged socle checkout, create the
signed annotated tag on the merge commit:

```sh
maelys-release cut . X.Y.Z --tag
maelys-release cut . X.Y.Z --tag --apply
```

The tag workflow verifies the signature, builds Linux x86_64, Linux arm64 and
macOS arm64 packages, attests provenance, publishes the GitHub release and
updates the Homebrew formula and bottles. Verify the published result:

```sh
gh release view vX.Y.Z
gh attestation verify ASSET --repo maelys-dev/maelys-egress
brew install maelys-dev/tap/maelys-egress
```

To adopt a newer socle without publishing, run `maelys-release adopt .` first,
read every impact line, then repeat with `--apply`. An adoption travels in the
next product release unless it changes something users receive.
